# Original alias API and delivery targets

Mailflare `71aa49b` (v0.5.2) returns updated alias lists after creation and
deletion. Native endpoints returned an ID or `{ok:true}` instead, used different
ordering/errors, and rejected dot/plus variants that the original accepts. Native
delivery selection could also choose a different mailbox for equivalent aliases
whose timestamps differed.

## Original evidence

`tests/source-alias-contracts.json` contains 58 responses from the unmodified
original alias handler and the complete persisted alias rows after each request.
The cases cover owners, ordinary owner accounts, every known shared grant,
unknown/unshared grants, disabled/personal mailboxes, missing Team entitlement,
validation order, malformed fields, active/inactive/foreign domains, literal
duplicates, dot/plus variants, list order and create/delete responses. Only the
generated alias identity and current creation time are normalized. Source hashes
are recorded. All fixture domains use `zone_id='manual'`, so the original skips
Cloudflare provisioning; no email is sent.

The previous standalone host binary matches six cases and fails 52. The updated
API matches all 58 responses and persisted states.

`tests/source-alias-routing.json` captures nine results from the unmodified
original resolver, bundled with its original Node SQLite adapter. It exercises
explicit aliases, dot/plus normalization, another domain, equivalent aliases
with different timestamps, primary-mailbox precedence, disabled targets,
cross-domain fallback and unknown addresses. The compared projection is the
delivery action and mailbox identity, not every internal resolver field.

The newer-equivalent-alias fixture reproduces a wrong native destination:
the original picks `routing-second`, while native creation-time ordering picks
`mailbox`. The source's domain/local-part index yields the captured order;
native lookup now explicitly orders by alias local part to retain that result.
The other eight cases remain matched. This is selected alias delivery evidence,
not a complete domain-rule or inbound processing audit.

```sh
bun scripts/serve-session-fixture.ts --reference /path/to/original-71aa49b \
  --before /path/to/previous-host-binary --after dist/mailrun-local --port 4810
bun scripts/capture-source-aliases.ts /path/to/original-71aa49b \
  /path/to/printed/mailrun-test-directory http://127.0.0.1:4810
bun scripts/capture-source-alias-routing.ts /path/to/original-71aa49b \
  /path/to/printed/mailrun-test-directory
bun test tests/source-aliases.test.ts tests/source-alias-routing.test.ts tests/routing.test.ts
bun scripts/smoke-aliases.ts dist/mailrun-local
```

## Native changes

- GET preserves source alias/domain ordering and DTO fields. POST and DELETE
  return the updated `{aliases}` list.
- POST validates with the source schema before management checks; DELETE checks
  the required alias ID before management checks. Permission failures retain the
  source 404 body. Missing/inactive/foreign domains and duplicate mailbox/alias
  addresses retain their distinct errors and statuses.
- Alias creation checks current mailbox management permission, active domain
  ownership and literal mailbox collisions in one typed SQLite transaction.
  The existing unique index and conflict-safe insert atomically reserve a literal
  alias address. Parallel identical creates produce one row. Distinct dot/plus
  spellings remain distinct records, as captured from the source; inbound
  normalization and primary-mailbox precedence still apply.
- Local aliases resolve behind the previously installed catch-all relay. Their
  ordinary creation/deletion does not publish/delete a Cloudflare rule per
  address. Cloudflare setup/resource failures are outside this manual-domain
  comparison; the native relay is provisioned and verified by receiving setup.

No persisted table, migration, backup table/group or format changes.

## Validation and remaining scope

All 937 host tests, generated SQL/coverage and strict TypeScript pass, including
the 78 focused alias/routing cases. The rebuilt standalone binary passes all 58
original alias API comparisons and the normal HTTP/WebSocket suite. Native Linux
CI and preview deployment are pending for this checkpoint. The compiled alias
comparison is added to Ubuntu CI before retaining its deployable artifact.

Full routing-rule CRUD, the remaining address-resolution combinations, provider
rule lifecycle/cutover, rendered/mobile alias workflows, external clients and
native guest resource/cold-start checks remain separate gates. Existing native
unsafe-regex and author-only draft guards are unchanged. This selected audit
does not establish full parity.
