# Original identifier formats

Earlier source comparisons normalized generated identifier values so unrelated
random values could be compared. They did not check namespace or random-part
length. Original Mailflare `71aa49b` (v0.5.2) uses NanoID 5.1.16 with 21 URL-safe
characters; the native common helper generated UUIDs and added an `id_` prefix
when called without an argument. Audit, folder, setup-mailbox and password-reset
row writers also used different namespaces.

## Reference evidence

`tests/source-identifiers-contracts.json` executes the unmodified original
`newId`, `generateApiKey`, `generateSessionToken` and `hashSessionToken` under
Node. It records bare/empty-prefix behavior and all 35 literal prefix classes
found in original writers. API-key evidence includes prefix width, secret shape,
bcrypt cost and successful verification; session evidence includes token shape,
hash length and a fixed synthetic input's hash. No generated secret values or
password hashes are retained in the fixture. The original lockfile and relevant
factory/writer modules are hashed, and the original NanoID version is recorded.

The existing send snapshot now records each normalized variable identifier's
actual prefix, suffix length and URL-safe alphabet check. Original captures were
regenerated by executing the pinned source: 83 session send/cancel outcomes,
72 public sends, 80 JMAP identity/submission outcomes and 45 automatic-reply
executions. These 280 comparisons retain their source state, revision, permission,
wire and complete object-key/hash checks. Values remain random; their formats
are compared independently instead of being normalized away.

The former generator and writer prefixes fail these checks. Initial diagnostic
probes also exercised source prefix classes separately; the final factory test
consolidates that matrix into one check, with six additional real writer and
legacy-compatibility tests. The first full run exposed the automatic-reply
snapshot's shared dependency; its original captures were regenerated with the
same format descriptors rather than dropping the check.

```sh
bun scripts/capture-source-identifiers.ts /path/to/original-71aa49b
bun scripts/capture-source-send.ts /path/to/original-71aa49b
bun scripts/capture-source-v1-send.ts /path/to/original-71aa49b
bun scripts/capture-source-jmap-submission.ts /path/to/original-71aa49b
bun scripts/capture-source-auto-reply.ts /path/to/original-71aa49b
bun test tests/source-identifiers.test.ts
```

## Native changes

The common server helper uses the same exactly pinned NanoID version and source
prefix semantics, including bare and empty-prefix calls. Audit rows use `aud`,
folders use `fld`, setup mailboxes use `mbx`, and password-reset rows are bare
identifiers while their tokens retain `prt`. API-key secrets reuse the common
secure generator with their existing `ep_` prefix, bcrypt policy and 12-character
lookup prefix.

New session tokens/rows and user IDs match source formats. Stored UUID user IDs
and older UUID session tokens remain usable, with no record or object-key rewrite.
There is no schema, backup table/group or data migration in this change.
Remaining user-facing setup/update text uses the Mailflare product name. The
GitHub repository and existing deployment keep their current names.

Tests compare the genuine source factory descriptors with native factories,
managed-key issuance/authentication, session issuance/hash/lookup, mail and auth
audits, folder creation and password-reset tokens/rows. A legacy user/session
case verifies both old and newly issued tokens against the same unchanged UUID
identity. Existing setup workflow checks now compare actual user/mailbox IDs
against the original classes.

## Verification and recovery

All 2,002 host tests, SQL generation/coverage, strict TypeScript and the production
host build pass. Compiled HTTP checks verify session cookies and row IDs, login
audit IDs, issued key/secret formats, folder creation/list lookup, first-account
setup user/mailbox IDs and restart/login. The existing 280 send/reply outcomes
also pass in compiled HTTP/cron/restart rehearsals with format checks. Final
native Linux and release evidence follows after verification.

The previously approved temporary recovery directory was absent after an
interruption. A fresh current export was recreated and verified: 53,609,521
bytes, current source `51b0a91` executable matching its CI checksum, private
environment, SQLite integrity/foreign-key checks, one account/five messages,
0071 applied and empty submission ledger. The owner selected a persistent
`mailflare-recovery` directory under their development `_experiments` folder.
The full archive and verification manifest are retained there outside the
repository, with directory mode 0700 and file mode 0600, and the copy's checksum
matches. Secret values and mailbox contents were not displayed.

This closes the common generated-ID format and identified writer namespace gap.
It does not prove every remaining protocol producer or provider-specific nonce
and wire behavior. Assistant/calendar producers, other allowed-handler/query/
permission matrices, paired rendered/mobile/keyboard states, external client
interoperability, original-data cutover, whole-guest cold/peak/concurrent capacity
and the original Vinext/Cloudflare performance baseline remain open. Native draft
body/file protection still awaits the existing explicit owner policy choice.
Full parity is not yet established.
